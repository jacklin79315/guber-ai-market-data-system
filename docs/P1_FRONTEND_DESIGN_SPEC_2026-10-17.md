## 1. 品牌與 Logo（硬性規則）
- 品牌圖檔：使用者在本次對話提供的**原始黑色幾何馬頭＋UBER 字樣完整 Logo**。
- **必須使用原圖本體**。不可裁切、重繪、改動輪廓、移動圖形、替換字體、扭曲比例、僅使用馬頭、加上其他造型；**唯一可接受的圖形變動是整體或局部顏色調整**，且不改變構圖與形狀。
- Logo 圖片目前由聊天附件提供，**尚未確認已放入 GitHub repo**；在取得原檔並正式存入前端資產目錄之前，不能用網路圖片、生成圖或其他馬頭 Logo 冒充。
- 深色主題中可將原圖黑色改為白色或高對比中性色，完整保留透明背景／原構圖。必要時在介面顯示完整原圖於純色底，避免損壞細節。

## 2. 視覺語言
- 深色系為預設且主要主題：深黑／炭灰底、清晰階層、少量高對比重點色；簡約、克制、現代科技感，不用雜亂漸層、霓虹堆疊或密集裝飾。
- 介面一律**繁體中文（台灣）**。專有名詞以中文優先，例如「開倉專家」「風報比專家」「勝率專家」「風險與倉位專家」「持有時間專家」「決策大腦」「等待」「退回」「核准」「拒絕」「歷史模擬」「自主訓練」「模型驗證」「回補」「資料完整性」。
- 必要的代碼識別（如 BTCUSDT、15m、API、模型版本）可保留；不得以大段英文當作 UI 導覽或狀態文字。
- 禁止將尚未實作的 AI、模型、訓練或 LINE 功能顯示為正常運作；應顯示「尚未啟用」及開發階段。

## 3. RWD 與 iOS 手機優先
- iPhone Safari 為優先測試平台；支援不同螢幕寬度及直向操作，桌面與平板亦適配。
- 正確處理 iOS viewport、安全區（瀏海／動態島／底部 Home 指示條）、固定底部導覽、軟鍵盤遮擋、滑動及觸控。
- 手機版使用單欄卡片與易點擊導覽；桌面版可用側邊導覽、多欄資訊；避免橫向溢出，資料表需可捲動或轉為卡片。
- 觸控目標至少約 44×44 CSS px，文字清晰可讀、對比充足；表單輸入不觸發 Safari 不必要放大。
- 兼顧載入效能、錯誤與空狀態、骨架載入、無障礙標籤、資料更新時間標示。

## 5. 工程安全與驗收
- 先盤點 GitHub 現有前端框架／目錄／Railway 服務，避免無意重建或干擾現有 collector。
- 讀取 Supabase 的資料健康應遵守 RLS 與角色矩陣；前端不得持有 service_role 密鑰；需實際測試非管理員權限。
- 不修改 Binance 原始資料、現有抓取／回補排程或 AI 模型。
- P1 完成需有 iPhone Safari 與桌面截圖或實測證據、功能頁面驗收、登入／權限測試、建置與部署成功證據。
- P0 依使用者最新決定已封版；P0 歷史未測風險保留但不再當作 P1 啟動阻擋條件。
