# 一般帳號管理安全規格

- 新增帳號使用者名稱採 3–40 字元英數與 _ -，首字須為英文字母。
- 新密碼必須 12–128 字元，包含英文字母及數字，不得包含帳號名稱。
- user001 為預定建立的一般帳號名稱；原先提出的 1234 不符合密碼規則，不會用於正式部署。
- 管理員後台新增帳號必須先驗證管理員 JWT 與 role=admin；不能只依前端顯示或請求中的 role 欄位。
- 使用 Supabase Auth 管理 API 建立使用者時，只能由後端使用安全儲存的服務端金鑰，絕不可放入前端。
- 一般帳號資料應存於具 RLS 的專用帳號表，採 Auth user ID 綁定；需支援停用及稽核。
- 建立 Auth 使用者及帳號資料的流程應有失敗回滾或補償機制，避免孤兒帳號。
- 正式實作前需完成後端憑證、資料表與 RLS、管理介面、整合測試。
- 目前僅完成帳號格式及密碼規則與自動化測試，尚未建立 user001。
