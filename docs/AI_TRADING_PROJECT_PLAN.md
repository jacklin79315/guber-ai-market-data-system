## 最高優先級規則（使用者明確指示，2026-10-16）

**嚴禁助理或開發代理自主新增、擴充或改變任何未經使用者事前明確許可的功能。**

1. 僅可執行使用者已明確核准的需求、修復及開發步驟；不得將「可能有幫助」視為授權。
2. 如有新功能、額外驗證、額外測試機制、架構調整、資料表或欄位、模型策略、部署流程、排程或其他範圍變更建議，必須**先提出建議、目的、影響、風險與替代方案，取得使用者明確同意後才可實作**。
3. 「繼續」僅代表繼續**已核准**的既定工作，不代表同意新的功能或範圍變更。
4. 修復既有功能時，以**恢復原本能力且最小變更**為原則；不得藉修復之名加入未經批准的功能。不得移除或繞過既有功能，尤其資料庫訓練紀錄寫入，除非使用者明確批准。
5. 執行前確認變更不會造成既有功能退化；執行後須交付可查核的證據，清楚區分「程式已提交」「工作已執行」「資料已寫入」「結果已驗證」。無證據不得宣稱成功。
6. 不得擅自啟用自動下單；此功能已由使用者要求從專案規劃排除。
7. 發現未列入核准範圍的需求或風險時，**停止該項擴充並向使用者請示**，不得自行決定。

## 原始資料與 Features 不可變更（使用者再次明確確認，2026-10-16）

- **原始市場資料與既有 Features 是訓練輸入，不是本輪修復標的；此限制針對助理擅自變更，不限制既有資料管線正常運作。**
- **必須維持既有正常運作：** Binance API 按原有機制持續取得最新原始市場資料並寫入資料庫；Features 引擎按原有機制持續計算、寫入及更新新資料對應的技術指標。既有合法排程、增量更新、正常資料維護與原有資料處理流程不因本條款停止。
- **本輪未經授權禁止變更：** 助理不得擅自修改資料收集 API、資料管線程式、既有技術指標公式、Features 定義、資料表／欄位或既有排程；不得擅自清空、批次重抓、回填、歷史重算、覆寫、遷移既有原始資料或 Features。
- 不得以「資料品質驗證」為理由擴張工作範圍，亦不得擅自更動上游資料處理。若遇上游資料問題，只能記錄證據與回報，取得使用者事前明確授權後才可處理。
- **唯讀限制只適用於本輪正在修復的下游 AI 訓練與交易回測程式對上游資料的存取；不適用於原本負責收集資料、計算及更新 Features 的既有服務。** 允許修復下游訓練、交易回測、迭代及其績效紀錄。

## 四策略是 AI 自主學習的四個獨立迭代對象（使用者再次明確確認，2026-10-16）

- 四策略固定為 `INTRADAY`、`ONE_TO_THREE_DAYS`、`ONE_WEEK`、`FIFTEEN_TO_THIRTY_DAYS`。
- **四策略不是單純的四種訊號顯示模式，也不是一次性回測項目；每一策略都必須各自進行 AI 訓練、交易回測績效驗證、逐輪反饋、候選模型比較及持續迭代。**
- 各策略的訓練紀錄、參數、交易績效、合格判斷與最佳模型必須可分別追蹤；不得混用不同策略的結果。
- 迭代依據是交易績效與既有模型評估規則，不得以單純方向預測分數冒充報酬率、勝率或交易評分。
- 原有績效目標：平均年化報酬率至少 10%、勝率至少 70%、平均交易評分至少 65 分；**目標不代表已達成**。每輪訓練須能檢視可用的交易績效與資格狀態。
- 恢復範圍限定既有自主訓練與績效閉環，不得擅自新增模型策略、風控規則、排程、資料庫欄位或自動下單。


## AI 自主交易決策、特徵學習與績效迭代（使用者確認，2026-10-16）

1. **每一次訓練都要完整模擬 AI 的交易決策：** AI 根據決策當下已知的技術指標與市場特徵，主動判斷有無交易機會，選擇 LONG、SHORT 或 WAIT；沒有足夠機會時不交易，不得強制產生交易。
2. **每輪必須經歷交易回測與結算：** AI 決策接入既有歷史交易回測，依原有進出場與交易評分機制結算已平倉交易；不得用方向預測正確率取代實際交易績效。
3. **每輪必須產出並保存三項核心結果：** 年化報酬率（annualized_return_percent）、勝率（win_rate_percent）、策略評分（既有 mean_score_q）；應呈現交易筆數、無法計算的原因與資格狀態，不得憑空填入數值。既有交易評分公式與風控、出場規則不擅自修改。
4. **AI 必須自主學習技術指標特徵的預測價值：** 不只調整 max_iter、learning_rate 等模型超參數，也應透過既有訓練資料與驗證回饋，改善對不同市場特徵、特徵組合與未來價格變化之關聯的學習和判斷；不得偷看未來資料、以驗證或 holdout 資料反向訓練。
5. **四策略各自持續優化：** INTRADAY、ONE_TO_THREE_DAYS、ONE_WEEK、FIFTEEN_TO_THIRTY_DAYS 各自訓練、回測、比較候選模型、保留最佳模型並進行下一輪迭代；不得將四個不同持有週期混成單一模型。
6. **允許跨策略比較，但不可直接以單一指標淘汰其他週期：** 比較年化報酬率、勝率、策略評分，並參考交易次數、回撤與獨立驗證是否合格；各策略保留獨立最佳版本及可追溯紀錄。
7. **既有績效目標維持不變：** 年化報酬率至少 10%、勝率至少 70%、平均交易評分至少 65；這是優化目標，不代表已達標，也不授權自行變更既有合格規則或評分公式。
8. **預期閉環：** 市場資料與 Features（下游唯讀）→ AI 特徵學習與未來預測 → LONG／SHORT／WAIT → 歷史交易回測 → 三項績效結算 → 候選模型比較 → 反饋學習 → 下一輪訓練。
9. **執行限制：** 此節確認既有自主學習目標；實作時優先修復現有程式，禁止擅自新增模型架構、技術指標、資料表欄位、排程或自動下單。涉及未定義的特徵選擇／模型替換規則時，先提出具體方案與影響並取得授權。


## 雙分析層 AI 決策架構（使用者明確批准，2026-10-16）

- **核准調整：** 在既有 AI 自主訓練流程中，將學習與判斷職責分為「價格結構分析」及「方向判斷分析」，再由交易決策層整合；這是經使用者事前確認的模型學習邏輯調整。
- **價格結構分析：** 以現有市場 K 線及 Features 學習支撐、壓力、價格區間及未來可達價格位置，輔助判斷開倉、止盈、止損。優先檢視既有歷史高低點、均線、布林通道、價格距離、ATR、K 棒與量能等訊息；不得把特定指標的用途寫死為唯一正確答案。
- **方向判斷分析：** 以現有 Features 學習未來多空方向、趨勢強度與動能，優先檢視均線及斜率、RSI、MACD、ADX、成交量等訊息；依不同策略週期各自訓練。
- **交易決策整合：** 結合兩層輸出判斷 LONG、SHORT 或 WAIT，並產生有依據的進場、止盈、止損；沒有合理交易機會時必須 WAIT。原有風控、交易評分與回測驗證規則維持不變，若需要更動須另行授權。
- **自主學習與迭代：** 四策略各自比較候選模型的真實模擬交易結果，逐輪改善方向與價格結構判斷；每輪保存年化報酬率、勝率、策略評分及資格狀態。不可用未來資料進行決策或使用 holdout 反向選模。
- **實作邊界：** 優先沿用現有 HistGradientBoosting 與既有 Features；不新增上游指標、資料表欄位、排程、自動下單，也不改動原始資料或 Features 引擎。先建立可回溯的兩層模型介面，再接回既有交易回測與迭代流程，逐步驗證，不得宣稱未實測的績效。


## 雙分析層獨立自主學習與持續適應（使用者明確核准，2026-10-16）

### 一、方法 B：方向與價格結構分開學習
- 採用「方法 B」：方向判斷 AI 與價格結構 AI 分別訓練、分別診斷誤差、分別探索與調整各自的訓練參數，不再要求兩層共用同一組超參數。
- 方向層學習多空方向、趨勢與信心；價格結構層學習支撐／壓力、可交易價格區間、進場區間、止盈區間及止損區間。區間應有依據與不確定性，不能把未來最高／最低價的預測直接宣稱為已驗證支撐壓力。
- 決策層整合兩層結果，判斷 LONG、SHORT 或 WAIT，並計算風險報酬比、建議投入資金比例與理由。止損區間仍需有明確失效價格供風險計算。
- 兩層可分別進步，但**正式模型資格仍依完整模擬交易的既有績效與驗證規則**判定，不得只因預測準確率上升便升級交易模型。

### 二、訓練達標後監控，監控期間仍持續學習
- 四個策略 INTRADAY、ONE_TO_THREE_DAYS、ONE_WEEK、FIFTEEN_TO_THIRTY_DAYS 各自獨立訓練、迭代、驗證、選拔及保留合格版本。
- 績效目標為年化報酬率至少 10%、勝率至少 70%、平均交易評分至少 65；三項需同時達標，並符合既有交易筆數、回撤、交易成本、資格及獨立驗證要求。目標不等於已達成，亦不保證未來獲利。
- **只有經驗證達標的策略版本，才能進入正式市場監控與訊號提醒；未達標策略繼續訓練，不阻礙其他已達標策略運作。**
- 市場監控持續讀取既有管線更新的最新原始行情與 Features，判斷市場結構與交易機會；訊號包含標的、策略、方向、進場價格區間、止盈價格區間、止損價格區間、風險報酬比、建議投入資金比例、判斷理由及訊號有效條件；無足夠機會時維持 WAIT，不強制交易。
- **監控與自主訓練並行**：已通過驗證的版本持續負責監控及提醒；背景訓練流程持續使用已完成、可合法取得的歷史資料迭代候選模型，追蹤市場變化、交易績效與模型失效跡象。
- 新候選模型不得直接取代正在監控的版本；必須通過與既有模型一致的獨立驗證、交易績效與風險資格審查，且在可比較條件下確認改善後才可升級。保留版本、參數、績效、驗證區間、升級理由及可回退紀錄；未通過者不升級。
- 持續適應的目標是改善報酬、勝率及策略評分，但不能保證三者每次迭代都同時上升。遇到市場環境變化、資料不足或績效惡化，須保留 WAIT／暫停該策略正式訊號的安全能力，不得為了達標而放寬既有風控或評分門檻。
- 嚴守時間順序與防止資料洩漏：訓練、驗證、獨立 holdout 不得混用；不能以 holdout 反覆調參，也不能讓當下交易決策取得未來資料。持續監控產生的新資料，須待完整形成可用歷史樣本後才能進入後續訓練。
- 僅提供**訊號提醒**，不進行自動下單。保留原始行情與 Features 管線正常運作，不擅自更改既有公式、排程、風控、評分或資料處理流程。

### 三、實作與驗收邊界
- 本節核准的是「雙模型獨立學習、達標後監控、監控與持續訓練並行」的目標及必要的下游訓練／模型管理邏輯，不代表核准任意新增指標、上游資料修改、額外資料庫結構、具體排程頻率、風控公式或訊號通道設定。
- 實作順序：雙層獨立訓練參數及診斷回饋 → 各策略候選模型交易回測與績效驗證 → 達標資格閘門及版本保存／回退 → 最新 Features 監控與區間訊號 → 監控不中斷的持續訓練與新版本升級。
- 驗收須能展示：各策略歷次訓練的年化報酬率、勝率、策略評分、回撤及交易筆數；雙層各自誤差與改善情況；當前監控版本與候選版本的差異；達標／未達標判定；實際監控訊號及 WAIT；候選版本未通過驗證時不替換正式版本。
- 任何尚未實作或未經實際測試的功能均不得宣稱已完成。新增排程或其他超出已核准邊界的改動仍須先取得使用者同意。


## 多倉位與多資產回測開發規劃（2026-10-16 使用者核准）

### 核心架構
- 策略不等於倉位：四個策略各自訓練、評估，但每個策略允許多筆持倉、多個交易對同時進場，同一資產可根據獨立有效訊號分批進場。
- AI 每次產生 LONG、SHORT 或 WAIT 都要留下可追溯的訊號；是否實際成交由資金與風險條件決定，不得因已有持倉而直接忽略交易機會。
- 訊號、交易執行、策略績效與整體投資組合績效分開記錄與評估。
- 保留四策略獨立績效，同時建立共同資金與曝險視圖，避免跨策略重複使用資金；同方向加倉必須有獨立理由及風險預算，反向訊號不得自動視為應對沖或反手。
- 各批次獨立追蹤成本、進出場、止盈止損、交易費用、最大有利及不利波動、持倉時長、未實現損益與出場原因；期末未平倉不得算成已平倉交易。
- 統計訊號品質、成交率、交易勝率、平均評分、年化績效、回撤、資金使用率及交易成本；同一行情的多次加倉需另外提供事件群組統計，避免重複計算獨立成功樣本。
- 跨資產 Features 及決策只能使用當時已知且已收線資料，保留訓練、驗證、holdout 的時間隔離。

### 現況與診斷
- 目前 PaperAccount 每個策略只能有一筆持倉，屬於需要改造的回測限制；既有十輪訓練與績效保留作舊版基準，不得刪除或覆寫。
- 既有兩年切分規劃為訓練 16 個月、驗證 4 個月、holdout 4 個月，驗證與 holdout 各有 30 天隔離期。
- GitHub Actions 38813257265 的驗證回測實際 K 棒：15m 2,976 根、1h 744 根、4h 186 根、1d 31 根，皆約 31 天；必須核對實際首末時間與窗口邊界，不能將其視為四個月完整回測。
- 15–30 天策略第 6 至 10 輪各門檻皆為進場一筆、平倉零筆、期末仍持倉；不是沒有交易訊號，單倉限制阻擋了其他進場機會。

### 已核准開發順序與驗收
1. 核對實際歷史資料讀取範圍、驗證窗口、隔離期與回測首末時間，建立可信基準。
2. 改造下游多倉回測引擎，支援多資產、同資產分批進場、獨立出場與共同資金管理。
3. 分離訊號及交易績效，追蹤未成交原因、未平倉部位與相關交易事件群組。
4. 整合跨策略投資組合曝險及資金占用；具體最大倉位數、加倉比例、風險額度、反向持倉處理與最長持倉時間須先提出方案，取得另行確認，不得自行設定。
5. 用相同時間窗口、成本、資料切分比較舊版單倉與新版多倉績效，展示完整交易與風險明細。
6. 通過回測與風險核算驗證後恢復四策略自主訓練與迭代；維持原定年化報酬率至少 10%、勝率至少 70%、平均交易評分至少 65，以及既有交易數、回撤、成本與獨立 holdout 門檻。
