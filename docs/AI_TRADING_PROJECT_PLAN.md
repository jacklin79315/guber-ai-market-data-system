# AI 交易系統開發規劃書：範圍與變更授權規範

## 最高優先級規則（使用者明確指示，2026-10-16）

**嚴禁助理或開發代理自主新增、擴充或改變任何未經使用者事前明確許可的功能。**

1. 僅可執行使用者已明確核准的需求、修復及開發步驟；不得將「可能有幫助」視為授權。
2. 如有新功能、額外驗證、額外測試機制、架構調整、資料表或欄位、模型策略、部署流程、排程或其他範圍變更建議，必須**先提出建議、目的、影響、風險與替代方案，取得使用者明確同意後才可實作**。
3. 「繼續」僅代表繼續**已核准**的既定工作，不代表同意新的功能或範圍變更。
4. 修復既有功能時，以**恢復原本能力且最小變更**為原則；不得藉修復之名加入未經批准的功能。不得移除或繞過既有功能，尤其資料庫訓練紀錄寫入，除非使用者明確批准。
5. 執行前確認變更不會造成既有功能退化；執行後須交付可查核的證據，清楚區分「程式已提交」「工作已執行」「資料已寫入」「結果已驗證」。無證據不得宣稱成功。
6. 不得擅自啟用自動下單；此功能已由使用者要求從專案規劃排除。
7. 發現未列入核准範圍的需求或風險時，**停止該項擴充並向使用者請示**，不得自行決定。

## 當前範圍提醒

目標是自主訓練、驗證訓練結果、逐輪回饋與持續改善 AI 市場預測能力；訓練歷史須可追蹤。任何超出已核准規格的新增功能均須另行取得許可。

## 變更提案格式

- 建議事項及原因
- 是否屬於原規劃（若否，明示「新增功能／變更」）
- 對現有功能、資料、成本及執行結果的影響
- 不採納的影響
- **等待使用者明確批准後才執行**


## 原始資料與 Features 不可變更（使用者再次明確確認，2026-10-16）

- **原始市場資料與既有 Features 是訓練輸入，不是本輪修復標的。**
- 本輪恢復自主訓練及績效閉環期間，**不得修改、重抓、清空、回填、重新計算、重新定義或遷移**原始市場資料、Features、相關表格、欄位、指標計算及資料收集流程。
- 不得以「資料品質驗證」為理由擴張工作範圍，亦不得擅自更動上游資料處理。若遇上游資料問題，只能記錄證據與回報，取得使用者事前明確授權後才可處理。
- 訓練與回測只能**唯讀使用**既有原始資料與 Features；允許修復下游訓練、交易回測、迭代及其績效紀錄。

## 四策略是 AI 自主學習的四個獨立迭代對象（使用者再次明確確認，2026-10-16）

- 四策略固定為 `INTRADAY`、`ONE_TO_THREE_DAYS`、`ONE_WEEK`、`FIFTEEN_TO_THIRTY_DAYS`。
- **四策略不是單純的四種訊號顯示模式，也不是一次性回測項目；每一策略都必須各自進行 AI 訓練、交易回測績效驗證、逐輪反饋、候選模型比較及持續迭代。**
- 各策略的訓練紀錄、參數、交易績效、合格判斷與最佳模型必須可分別追蹤；不得混用不同策略的結果。
- 迭代依據是交易績效與既有模型評估規則，不得以單純方向預測分數冒充報酬率、勝率或交易評分。
- 原有績效目標：平均年化報酬率至少 10%、勝率至少 70%、平均交易評分至少 65 分；**目標不代表已達成**。每輪訓練須能檢視可用的交易績效與資格狀態。
- 恢復範圍限定既有自主訓練與績效閉環，不得擅自新增模型策略、風控規則、排程、資料庫欄位或自動下單。
